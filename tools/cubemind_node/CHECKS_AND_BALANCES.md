# Checks and balances — what to build (reference for the programmer)

Grounded in how good self-improving systems are built, but shaped to OUR vision (the field, the heart/mind, nothing stops).
The programmer builds the self-audit from this; it is not pre-built.

## What we already have (keep and verify, don't duplicate)
- Separate evaluator: the referee argues against every result, and an independent tester checks the code — not self-grading.
- Signed audit trail: every record and link is hashed and signed; the whole chain can be verified.
- Guardrails: code is proposed to the workbench and syntax-checked, never run on its own; markers and names outside the vocabulary are rejected.
- Memory + reflection: the ledger and neural web are the memory; checkpoints turn work into lessons.
- Monitoring + self-healing: the maintenance man reads alerts, applies known fixes; the safety net keeps things moving.
- Human-in-the-loop: Danny reviews the workbench before anything runs.

## What to add (build these as a self-audit pass, proposed in the workbench)
1. **Ledger check:** sample recent records and confirm they verify against the owner signature; flag any that do not.
2. **Part-liveness check:** for each part in SYSTEM_MAP, confirm it has acted recently (the subconscious is encoding, the mapper is addressing, the programmer is acting, the ramp is advancing). Flag a starved part.
3. **Balance check:** the neural web's seven scales are not lopsided; lanes are not all piling into one address.
4. **Memory-poisoning guard:** a lesson or auto-upgrade is a proposal, never a fact; flag a lesson that contradicts a locked result, and never let one rewrite a hashed record.
5. **Convergence/cost cap:** stop an improvement loop when gains fall below a threshold or an attempt cap is hit, so it never spins.
6. **Drift guard:** watch for a role defending a wrong answer instead of fixing it; the referee's FINDING rate staying in range is the signal.
7. **Write BALANCE.md** each pass: every check with PASS/FLAG and what to do; post a card; file it as a signed record.

## Constant connection-seeking (also build)
Every so often, look across the parts and the AI knowledge network for a NEW connection or a better way one part could help another, and
propose it (as code in the workbench). The system should always be hunting for a new link or improvement, within these checks.
