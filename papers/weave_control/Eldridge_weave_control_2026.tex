\title{Weave Control and the Evidence Atlas: One Model Driving Four Toolkits, with a Strict Count of What Counts as Evidence}
\author{Danny Eldridge}
\email{dannyeldridge54@gmail.com}
\affiliation{Independent researcher, Oklahoma City, Oklahoma, USA}
\date{20 November 2026}
\begin{abstract}
We describe two open tools built around the Weave/SERAPIS model~\cite{P1,P2,P3}. \emph{Weave Control} runs one parameter set through nine levels (inflation, lepton flavour, quarks, light elements, late universe, colliders, galaxy gamma line, neutron stars, sky) using four existing toolkits, and reports each level's numbers, the data they are compared with, and a status (pass, tension, fail, open), with the links that carry one level's output into another. The \emph{Evidence Atlas} lists every compared quantity (58 rows) with a label (prediction P, fitted F, assumed A, standard physics S, open G), a timing (locked before data, or post hoc), a kind (match, bound, comparison) and whether it is inherited from another row. Only headline P rows that are not post hoc and not inherited count as evidence. Under this rule the model's score is 1 pass, 2 tension, 1 fail and 1 open; nine further headline predictions are consistent but do not count (6 pass, 1 tension, 2 fail). No test has yet used data released after its prediction. We give the rules, the levels, how the tools are tested and packaged, and their limits. This is a methods note; it adds no new physics claim.
\end{abstract}
\keywords{reproducibility; pre-registration; scientific software; cosmology; inflation; dark energy; flavour; evidence accounting}

\section{Why}
A model that touches inflation, flavour, dark matter, dark energy and colliders produces many numbers. It is easy to count every agreement as support. We built one tool to run the whole chain from one set of inputs, and a second to state, row by row, which agreements could have failed and were fixed before the data. Both are in the public repository~\cite{REPO}.

\section{Weave Control}
\textit{Engine.} \texttt{tools/weave\_control/engine.py} defines a default parameter set and nine level functions. Each returns its inputs, outputs, the comparison data with sources, ``pulls'' (signed distances in $\sigma$ or pass/fail against a limit), labels, and links to other levels. A level's status is \emph{fail} if any pull is a FAIL or $|{\rm pull}|\ge3$, \emph{tension} for $|{\rm pull}|\ge2$, otherwise \emph{pass}, or \emph{open} if nothing is compared.

\textit{Links.} Outputs feed other levels: the dark-sector choice sets $\Delta N_{\rm eff}$ for the light elements; one wino mass drives both the collider and the gamma-line levels; the galaxy level hands science targets to the sky level; the quark modulus mass sets a dilution that shifts $N_*$ at the inflation level.
\textit{Interfaces.} A local HTTP server and a browser UI (one panel per level, SVG charts, parameters in the URL, JSON download), a command-line entry (\texttt{aegis control}), and an offline snapshot (a grid of precomputed level states, no interpolation) that the Android build uses because a phone cannot run the engine.
\textit{Guarding against self-deception.} Locked fit results (for example the full-Planck dark-energy fits) are shown as fixed bars marked LOCKED that do not move with the knobs; measurements are quoted unrounded with sources; the gamma-line level uses the more conservative end of each theory range.

\section{The Evidence Atlas}
\texttt{tools/evidence/atlas.py} collects every compared quantity from the engine and the dashboards and adds four fields fixed by a pre-registered table (\texttt{PREREG\_EVIDENCE\_ATLAS} with two recorded deviations): label, timing, kind and inherited. A row is \emph{evidence} only if it is a headline P row, its timing is not post hoc, and it is not inherited from another row. Everything else is reported but does not count.

Totals: 58 rows (42 P, 8 F, 3 A, 3 S, 2 G); 42 pass, 3 tension, 5 fail, 8 open overall; strict evidence 1 pass, 2 tension, 1 fail, 1 open (Table~\ref{tab:ev}); consistent-not-evidence 6 pass, 1 tension, 2 fail. The fitted spectral tilt $n_s$ is labelled F and never counts; the TM1 neutrino assignment, adopted after JUNO excluded TM2, is post hoc; the dark-matter row stays open until the direct-detection limit at 13\,GeV is properly sourced. The atlas is exported as CSV/JSON with the git hash; the v3.4 export is archived with Ref.~\cite{P3}.

\section{Testing and packaging}
Engine tests (15) check every level runs without error, the Koide and Brannen numbers, the light-element response to the dark sector, the ATLAS limit behaviour, the quark level (rung-1 $|\epsilon|=0.0236$, the $\tau_q$ window flips at $10^9$\,GeV), and the gamma-line recipe; atlas tests check the classification rules. A command-line self-test runs every level. Windows, macOS and Linux executables are built by continuous integration and must pass that self-test; Android APKs (sky map, dashboard, Weave Control) are built the same way and published to a download branch.

\section{Limits}
The status rule is simple and uses marginal pulls (no correlations). Several comparisons use summary likelihoods rather than full data. Labels and timings are judgements, fixed in advance and changed only through recorded deviations; a different but reasonable table could move a row between ``evidence'' and ``consistent''. The tools organise and check the model; they do not make it more likely to be true.
