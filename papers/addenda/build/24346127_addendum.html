Status update, 20 November 2026

Addendum to: Lock Before You Compute v2.1 (Zenodo record 24346127) · Danny Eldridge, independent researcher, Oklahoma City, Oklahoma, USA · dannyeldridge54@gmail.com

Status update, 20 November 2026. No errata were found. Four lessons since publication. (1) The first recorded lapse of rule 1: one lock (Q7, quark sector) was committed but, because a push failed, was not yet public when its script ran. The hash verifies and there was no rerun. It is disclosed in a deviations file. Pushing must be confirmed before running, not assumed. (2) Deviations files are now routine: 139 against about 840 locks. They also record changes that make a rule stricter after review. (3) Counting evidence needs its own locked rule. The project's evidence atlas now counts only headline predictions that are neither post hoc nor inherited from standard physics. It tags each row by timing and kind, and requires ΔAIC < −2 for model comparisons. A referee found a bug in the code that applied this rule (an "open" row was counted), so counting code needs tests too. The strict tally is 1 pass, 2 tensions, 1 failure and 1 open item. No test has yet used data released after its prediction, so "freeze and wait" is still waiting. (4) Further worked examples: a stop rule ending in a null result (D1723), a nested-model check that exposed an unconverged fit (D1724), a locked failure kept as a failure (D1725), and a significance claim withdrawn once model spread was included (D1743). See "Weave Control and the Evidence Atlas" (doi:10.5281/zenodo.24399447).
