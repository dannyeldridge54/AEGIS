# DEVIATIONS for PREREG_A8d (written before the rerun)
D1 (crash, test-data generator, 17 Nov): run 1 wrote the synthetic tiles with repr() of numpy scalars, which NumPy 2 renders as "np.float64(…)"; the CLI therefore parsed no numbers (it processed 0 stars, as it should for unparseable fields) and the check crashed when computing the expected selection. Fix: the generator writes repr(float(x)) — plain decimal strings as in real Star Mapper tiles. No change to mapper_orbits.py or to any criterion. Single rerun; verdict from it.

D2 (schema, written 18 Nov 2026 before any PC run): the real Star Mapper tiles on Danny's PC (repos/AEGIS/ufe-v2/cosmos_map/tiles/L5, 12,288 tiles, 17 GB) are not raw Gaia columns. They hold derived columns: source_id, ra, dec, l, b, dist_pc, dist_plx_pc, dist_bj_pc, g_mag, bp_rp, ruwe, pmra, pmdec, rv, ... and no parallax_error. Run as locked, select() keeps 0 stars (checked on 10 tiles: 34,344 stars, 0 kept). Fix: an input adapter, used only when a row has 'rv' and no 'radial_velocity':
  radial_velocity = rv; r_med_geo = dist_bj_pc; parallax = 1000/dist_plx_pc (mas); phot_g_mean_mag = g_mag.
  The parallax_over_error > 5 cut cannot be applied (no error column). Replacement quality cut [proxy, stated]: ruwe < 1.4 AND |dist_plx_pc/dist_bj_pc - 1| < 0.2 (parallax and Bailer-Jones distances agree within 20%, the same 20% fractional scale as plx/err > 5). Rows on the Gaia-column path are unchanged. Output flags gain 'proxy_cut'. Sample of 30 random tiles: 580,767 stars, 90,271 with rv; est. ~33M rv stars before the agreement cut.
  Acceptance before the full run: (a) the A8d synthetic test still passes unchanged on the Gaia path; (b) on 2 real tiles the adapter keeps > 0 stars and every output row is finite with 0 <= ecc < 1 and rperi <= rapo.

D3 (check script, written 18 Nov 2026 before the rerun): theory/janus_astro/a8d_check.py was written for the MWPotential2014 path (A8d's lock) and compares against fast.orbits_fast. Since D10 (PREREG_D10_mcm17_default) the CLI default is McMillan17 and writes to hyperion_mcm17/, so the unmodified check finds no output (KeyError). Fix: the two MO.run calls pass model='MWPotential2014' explicitly — the path A8d locked. No change to mapper_orbits.py, the criteria M1–M4, or the synthetic data. The McMillan17 path stays covered by D10's own check. Single rerun; verdict from it.

D4 (full PC run model, 18 Nov 2026 22:20 UTC, before any result was read): the full run on Danny's PC switches from the D10 default (McMillan17) to MWPotential2014 — the path A8d itself locked — because McMillan17 is CPU-bound at ~1 orbit/s/core (measured: 15 stars/s single process, ~18 stars/s with 12 workers; ~10 days for ~10M stars), while the MWPotential2014 numba path runs ~2,700 stars/s (~1 h). Danny agreed 16:19 CT. Run: queue job HYPMAP4, WSL Python (Windows Python's astropy DLL is blocked by Windows Application Control; that setting is not changed), --workers 8, output cosmos_map/hyperion (the MWPotential2014 outdir, separate from the partial McMillan17 output, which is kept). The --workers option only parallelises tiles; serial and parallel output are byte-identical (tested both models). No change to select(), the D2 adapter, the criteria or the check. The McMillan17 full run stays open under D10 (later, slower).
